# 已知限制与后续提醒

以下行为暂时保留，后续继续调整工程保存和撤销模型时需要重新评估。

## 参考图持久化不包含原始图片与裁切状态

裁切后的参考图会在浏览器本地编码为 WebP Blob 并保存到 IndexedDB，参考图开关与
透明度会随 `localStorage` 存档恢复。用户原始图片、裁切位置和裁切缩放比例仍然只在
当前页面会话中保留。

因此刷新页面后可以继续对照已经裁切好的参考图，但不能重新打开原裁切区域进行调整。
如果未来需要恢复完整导入工程，需要另外保存原始图片 Blob 和裁切参数，并评估存储
空间、隐私说明和清理策略。

## 撤销区分文档状态与视图状态

撤销和重做快照会保存固定 24×24 像素矩阵、文档元数据、编辑器色板和当前参考图
资源。导入与清空均可完整恢复对应的像素和参考图，历史上限为100步；不再被历史引用
的参考图 WebP 会从 IndexedDB 自动清理。

以下辅助视图状态不进入撤销栈：

- 参考图开关和透明度；
- 裁切状态；
- 画布缩放与平移位置。

这是当前明确采用的产品语义：撤销恢复作品文档，不改变用户正在使用的观察方式。
如果未来决定让视图状态也参与撤销，需要同步修改快照结构、浏览器回归条目和存储
资源评估。

## 延后移除服务器图片转换子系统

当前网页已经只在浏览器本地完成图片转换，长期部署方向是让服务器只承担静态页面、
作品保存和凭码读取。`convert_image.py`、Pyxelate 转换 API 与相关科学计算依赖目前
仍暂时保留，避免在保存与分享等其他功能尚未稳定时进行高风险的大范围删除。

在满足以下条件前，不执行该清理：

1. 其他计划功能已经完成并通过完整回归；
2. 当前可运行版本已经提交并推送，建立明确的 Git 回退点；
3. PostgreSQL 作品数据、部署配置和必要本地资源已经完成可恢复备份；
4. 已确认生产环境不再需要 CLI、`POST /api/v1/convert` 和短期预览接口；
5. 已安排清理后的 Docker 镜像构建、同源启动和浏览器验收。

届时必须作为一个完整变更统一检查，不得只删除 `convert_image.py`：

- 删除转换 CLI、转换核心、上传校验、子进程 worker 和预览缓存；
- 删除 `/api/v1/convert` 与 `/api/v1/results/{result_id}/preview.png`；
- 清理转换响应模型、错误类型、限流分支和相关环境变量；
- 从生产依赖移除 Pyxelate、NumPy、Pillow、SciPy、scikit-image、
  scikit-learn、Numba、Matplotlib 和 python-multipart；
- 将仍被测试素材使用的 Pillow 等工具按需移动到开发依赖；
- 删除 Docker 中仅供 Pyxelate 安装和科学计算运行使用的 Git、`libgomp1`
  与转换临时空间配置；
- 调整或移除转换器、视觉基线、并发、超时和上传接口测试；
- 更新 README、API、部署文档、许可证说明和 GitHub Actions；
- 最后重新生成 `requirements.lock` 与 `requirements-prod.lock`，比较镜像体积，
  并验证作品保存、凭码读取、前端本地转换和全部导出功能。

该事项属于“完成其他功能并备份后再执行”的待办项，不应在普通依赖整理中顺手处理。
