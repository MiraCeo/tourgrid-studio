# 阶段三：前端与转换 API 集成

当前阶段采用渐进式改造：保留现有 Canvas 编辑器的绘图、裁切、导航器和图纸导出行为，在验证 API 链路后再把单文件前端拆成职责清晰的静态资源。

## 已完成

- FastAPI 根路径 `/` 直接提供编辑器，前端与 `/api/v1` 保持同源。
- 裁切区按用户当前缩放和位移生成正方形 PNG Blob。
- 默认通过 `POST /api/v1/convert` 使用 `natural-64-v1`、`direct`、`none` 参数转换。
- 前端严格校验响应尺寸和 `hexPixels`，然后直接写入编辑器像素矩阵。
- 转换过程中显示上传状态，并支持使用 `AbortController` 取消。
- 服务端错误会保留裁切窗口并显示原因，不会自动改变算法。
- 原有浏览器 K-means 转换作为明确标识的离线备用模式保留。
- API 色板会加载到“巡展像素”色板区域，服务器转换结果可以显示色号。
- 导入操作纳入统一撤销/重做快照，快照同时保存网格尺寸。
- 增加颜色种类和已绘制格数统计。
- 分开导出原始尺寸 PNG、16 倍最近邻预览图和原有图纸。
- `Ctrl+S` 直接导出原始尺寸 PNG。
- HTML、CSS 和 JavaScript 已迁移到 `frontend/`，FastAPI 负责提供同源静态资源。
- localStorage 使用 schema v3，能够迁移旧版存档并保存来源、色板和转换器版本。
- 转换状态区区分图片上传与服务器处理，失败后可重试，重复提交会被禁用。
- 裁切区支持鼠标、单指移动和双指缩放。

## 本地运行

```powershell
.\.venv\Scripts\tourgrid-api.exe
```

打开：

- 编辑器：`http://127.0.0.1:8000/`
- API 文档：`http://127.0.0.1:8000/docs`

不要直接双击 HTML 作为日常启动方式。同源运行可以避免跨域配置，并保证色板和转换接口使用同一个服务版本。

## 模块边界

- `storage.js`：存档校验、序列化和旧版本迁移。
- `conversion-api.js`：服务器响应矩阵校验、参数描述和错误映射。
- `state.js`：编辑器状态、元数据与色板数据。
- `editor.js`：Canvas 绘制、撤销重做和导航器。
- `export.js`：原始 PNG、最近邻预览和图纸。
- `import.js`：裁切、API 上传、取消重试和本地备用算法。
- `app.js`：工具、色板选择、快捷键及页面控制。

浏览器本地备用结果仍不保证属于巡展 64 色色板，界面中会明确提示。上传原图只用于本次请求，服务器不会长期保存。
